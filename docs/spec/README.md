# 같이놀개 M1 계약 문서 안내

이 폴더는 같이놀개 M1을 구현하거나 리뷰하는 사람이 제품 범위, REST API, 데이터 구조와 상태 전이를 같은 기준으로 이해하기 위한 문서 묶음이다.

이 README는 안내서이며 계약 정본이 아니다. 문서가 충돌하면 아래 우선순위를 따른다.

1. 제품 범위·정책: `00_최신_제품정책.md`
2. REST 계약: `04_M1_OpenAPI.yaml`
3. 사람이 읽는 API 설명: `04_M1_API_명세.md`, `02_M1_API_계약.md`
4. 목표 데이터 구조: `01_M1_통합_ERD.md`, `01_M1_통합_ERD.sql`
5. 실제 적용 물리 스키마: `src/main/resources/db/migration`의 Flyway Migration
6. 상태 계약: `03_M1_상태전이.md`
7. 일정·담당: `04_M1_마일스톤_WBS.md`

## 3분 요약

- 회원가입은 이메일과 동네 선택으로 완료한다. 이메일 인증·비밀번호 재설정·회원탈퇴는 M1 범위가 아니다.
- Pet이 없거나 Active Pet이 없으면 L1이다. L1은 시드 셋로그 3개만 볼 수 있고, Active Pet을 선택한 L2부터 반응·인사·채팅·친구·카드를 사용할 수 있다.
- M1 셋로그는 서버가 미리 준비한 S3 영상 3개다. 사용자 업로드는 M2다.
- 인사를 보내면 친구가 아니어도 DIRECT 방과 최초 메시지가 즉시 생성된다. 상대 답변 전에는 추가 메시지를 보낼 수 없다.
- 친구는 채팅 시작 조건이 아니라 관계를 유지하는 기능이다. 상호 PENDING 요청은 자동수락한다.
- 차단과 신고는 M1이다. 신고가 접수되면 관리자는 해당 DIRECT 방의 전체 메시지를 증거로 조회한다.
- 약속 카드는 최근 24시간 내 사용자 TEXT만 문맥으로 사용한다. 문맥 부족이나 AI 실패 시에도 빈 폼을 반환한다.
- M1은 폴링 방식이며 Push, 읽음 표시, 메시지 수정·삭제, 이미지·파일 메시지를 제공하지 않는다.

## 구현할 때 주의할 경계

- `04_M1_OpenAPI.yaml`에 없는 endpoint를 M1 API로 임의 추가하지 않는다.
- 런타임 `/v3/api-docs`는 구현 상태 확인용이며 계약 정본이 아니다.
- Pet 생성 Commit과 첫 Active Pet 지정 Commit은 분리한다. 후자가 실패해도 생성된 Pet은 유지한다.
- Provider가 canonical 등록번호를 주지 않으면 인증 Attempt는 `REJECTED`이며 수동 Pet 등록은 계속 허용한다.
- 일반 USER에게 범용 미디어 업로드 API를 개방하지 않는다.
- 사용자 메시지 입력은 `TEXT`만 허용한다. `CARD`, `SYSTEM`은 서버가 생성한다.
- 욕설 자동 차단과 일일 AI 검열은 M1에 없다. 신고 후 관리자 검토가 M1 정책이다.

## PR 리뷰 시작점

1. 변경 endpoint가 `04_M1_OpenAPI.yaml`과 일치하는지 확인한다.
2. 상태 변경이 `03_M1_상태전이.md`와 DB CHECK를 위반하지 않는지 확인한다.
3. M1 제외 기능을 다시 노출하지 않았는지 `00_최신_제품정책.md`에서 확인한다.
4. 오류는 기본적으로 `400`, `403`, `404`, `409`를 사용하고 별도 상태는 endpoint 계약에 명시된 경우만 사용한다.
