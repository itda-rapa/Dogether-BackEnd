# 같이놀개 M3 상태 전이

## 1. OAuthLoginCode

```text
ISSUED → CONSUMED
ISSUED → EXPIRED
```

- code는 짧은 수명·1회용이다.
- CONSUMED code 재사용은 `410 OAUTH_LOGIN_CODE_CONSUMED`, EXPIRED code는 `410 OAUTH_LOGIN_CODE_EXPIRED`다.

신규 OAuth 사용자:

```text
LOGIN_CODE EXCHANGED → SIGNUP_REQUIRED → PROFILE_COMPLETED → TOKEN_ISSUED
                                  └────→ SIGNUP_TOKEN_EXPIRED
```

## 2. Pet

```text
ACTIVE ────→ DELETED
SUSPENDED ─→ DELETED
```

- 여기서 `ACTIVE`는 `PetStatus` 값이다. 사용자의 현재 대표 반려견(`user.active_pet_id`)이면 대체 Pet 선택 전 삭제를 거절한다.
- `DELETED ↔ deleted_at IS NOT NULL`.

## 3. Media

```text
INIT → UPLOADED → COMPLETED
  └──────┴──────→ FAILED

StorageDeleteJob:
PENDING → PROCESSING → COMPLETED
             └──────→ RETRY → PROCESSING
             └──────→ FAILED
```

- `UPLOADING`은 클라이언트 전송 상태이며 서버의 `MediaStatus`에는 저장하지 않는다.
- Chat 첨부는 UPLOADED/COMPLETED만 가능하다.
- 물리 삭제 진행 상태는 Media가 아니라 `StorageDeleteJobStatus`로 관리한다.
- 신고 Evidence 보존 대상은 정책 확정 전 물리 삭제 금지.

## 4. ChatMessage

```text
CLIENT SEND
  → 권한·typed payload·원본 검증
  → STORED
  → DIRECT realtime 또는 Kafka PUBLISHED
  → DELIVERED
```

- 같은 `clientMessageId`는 기존 메시지를 반환한다.
- TEXT는 body, IMAGE/VIDEO는 attachment, SETLOG_SHARE는 setlog만 허용한다.
- AI 분석은 STORED/DELIVERED 뒤 별도 분기이며 전달 상태를 바꾸지 않는다.

## 5. MeetingVerification·Meeting

```text
NOT_SUBMITTED
  → WAITING_COUNTERPART
  → GPS_CONFIRMED → MEETING_CONFIRMED
  → CODE_REQUIRED → CODE_CONFIRMED → MEETING_CONFIRMED
  → REJECTED / EXPIRED
```

- 첫 유효 제출은 상대 대기.
- 두 위치가 시간·거리·accuracy 조건을 만족하면 GPS_CONFIRMED.
- accuracy 부족은 CODE_REQUIRED.
- 카드 취소·시간 만료 후 제출은 거절.

## 6. Review·Footprint

```text
MEETING_CONFIRMED
  ├→ REVIEW_SKIPPED
  └→ REVIEW_SUBMITTED → FOOTPRINT_GRANTED 또는 FOOTPRINT_DUPLICATE_DAY
```

- Review는 Pet당 Meeting 1회.
- Footprint는 후기 제출자에게만 지급.

## 7. RiskSignal·SafetyCase

```text
EVENT RECEIVED
  → DUPLICATE_IGNORED
  → RECORDED → BELOW_THRESHOLD
             → CASE_OPEN

OPEN → REVIEWING → DISMISSED
                 → WARNING_RECORDED
```

- Case action은 append-only 감사 이력을 남긴다.
- 자동 SUSPENDED 전이는 M3 범위가 아니다.

## 8. AI Moderation

```text
MESSAGE_DELIVERED
  → RULE_NOT_MATCHED
  → RULE_MATCHED → AI_PENDING
                 → AI_SCORED → RISK_SIGNAL
                 → AI_FAILED/TIMEOUT
```

- FAILED/TIMEOUT은 메시지 전달을 되돌리지 않는다.
- Retry 횟수 소진 후 DLQ 또는 기록만 수행한다.

## 9. WalkSession

```text
RECORDING → COMPLETED
RECORDING → CANCELED
RECORDING → EXPIRED
```

- RECORDING에서만 points를 추가한다.
- 같은 sequence/clientBatchId 재전송은 멱등 처리한다.
- COMPLETED 뒤 서버가 거리·시간을 확정한다.

## 10. Board Comment

```text
PUBLISHED → UPDATED → DELETED
PUBLISHED → DELETED
```

- 삭제 부모에 자식이 있으면 tombstone 표시를 권장한다.
- 자식 댓글의 parent는 같은 Post의 depth 0 댓글이어야 한다.
- 기존 응답 호환을 위해 목록은 flat 구조이며 `createdAt, commentId` 오름차순 cursor를 사용한다.
- 페이지 경계에서 부모와 자식이 분리될 수 있으므로 Client는 `parentCommentId`로 연결하고 같은 페이지에 부모가 있다고 가정하지 않는다.
