# M3 백엔드 결정사항·리스크 체크리스트

## 1. 회의 확정사항

- 김승균이 만남 확인·후기·발자국을 담당한다.
- 노동훈이 Pet 삭제, 게시글 도움 표시, Google·Naver OAuth, 이미지 수정·삭제를 담당한다.
- 박선이 Dashboard, 채팅 Media, Setlog 공유, 위험 신호 운영, 배포를 담당한다.
- 이정수가 AI 검열, 지도·GPS·Place·산책 경로, Open Chat Media를 담당한다.
- 채팅 Media는 박선(Media), 김승균(DIRECT), 이정수(Open Chat)가 계약으로 분리한다.
- 위험 신호는 각 도메인이 event를 생산하고 박선이 저장·집계·관리자 운영을 담당한다.

## 3. 주요 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| Chat DTO가 DIRECT/Open Chat에서 분리 | Front 분기·오류 증가 | G1에서 typed payload 동결 |
| Media URL DB 저장 | URL 만료·정보 노출 | mediaId 저장, 조회 시 재서명 |
| Setlog 원본 복제 | 삭제·차단 후 노출 | setlogId 참조, 접근 불가 payload |
| 위치 판정 책임 중복 | 결과 불일치 | 이정수 validation, 김승균 meeting 판정 |
| 위험 event 중복 | 점수 과다·오탐 | eventId unique와 멱등 소비 |
| AI 장애가 채팅 차단 | 핵심 기능 장애 | 채팅 전달과 AI 비동기 분리 |
| Pet 삭제 참조 불일치 | Chat/Meeting 오류 | 도메인별 보존·정리 정책 계약 |
| Dashboard COUNT 과부하 | 관리자 API 지연 | 기간·상한·인덱스·쿼리 측정 |
| Media/Setlog N+1 | 피드·채팅 지연 | batch hydration·쿼리 수 테스트 |
| 기능 과다·계약 지연 | 26일 동결 실패 | 21일 계약 동결, 부가 UI부터 축소 |
