# M3 백엔드 연동 계약 및 의존성

## 1. 책임 경계

| 연동 | 제공자 | 소비자 | 책임 |
|---|---|---|---|
| Media 업로드·다운로드 | 박선 | 김승균·이정수·노동훈 | 소유권, 상태, MIME/크기, S3, batch URL |
| DIRECT Chat | 김승균 | Front·박선 | 방 권한, REST/WS, typed message, Evidence |
| Open Chat | 이정수 | Front·AI·박선 | Kafka/Consumer/STOMP, ordering, retry/DLQ |
| Setlog 공유 | 박선 | 김승균·이정수·Front | setlogId, summary, 접근·삭제 상태, 상세 route |
| Location/Place | 이정수 | 김승균·노동훈 | 좌표·accuracy, Place ID, Provider, 지도 이동 |
| Meeting | 김승균 | Front·박선 | 양쪽 확인, 시간·거리, 코드, 후기·발자국 |
| Risk event | 각 도메인 | 박선 | 원천 event 생성, source 식별자, actor/target |
| Risk 운영 | 박선 | 관리자 Front·김승균·이정수 | 저장·집계·Queue·감사·Dashboard |
| AI 판정 | AI 담당+이정수 | 박선 | type/score/reason, timeout, 최소 문맥 |
| Board Place | 노동훈 | 이정수 | 게시글 placeId, 장소 요약, 지도 이동 |

Board → DIRECT 연결은 Board가 active Post/Comment의 author Pet identity·visibility와 Active Pet 호출 권한을 검증하고 Chat의 `ensureDirectRoom(...)` 공개 계약을 호출하는 소비자 계약이다. Chat은 Pet pair 정규화, 기존 room 재사용, Participant 생성, 중복 방지와 `CHAT_ROOM_NOT_FOUND` existence hiding을 소유한다. Board는 Chat room/Participant Entity와 Repository를 직접 조합하지 않는다.

## 2. Chat typed message 계약

공통 의미:

```text
TEXT | CARD | IMAGE | VIDEO | SETLOG_SHARE | SYSTEM
```

공통 원칙:

- REST history, DIRECT WebSocket, Open Chat Kafka/Consumer가 같은 필드 의미를 사용한다.
- IMAGE/VIDEO는 `mediaId`, SETLOG_SHARE는 `setlogId`를 저장한다.
- Presigned URL과 Setlog 전체 snapshot을 메시지 DB에 저장하지 않는다.
- 조회 시 접근 가능한 원본을 batch hydrate한다.
- 삭제·차단·권한 없음은 원본 내용을 숨긴 대체 payload로 반환한다.
- `eventId` 또는 `clientMessageId`로 중복 SEND를 방지한다.

결정할 필드:

- 메시지당 첨부 개수
- MIME·크기·영상 길이
- DIRECT/Open Chat 허용 범위
- 신고 Evidence가 있는 첨부의 보존 기간
- Setlog current reference/snapshot 정책

## 3. Location·Meeting 계약

Location 입력 최소 필드:

```text
latitude, longitude, accuracyMeters, capturedAt
```

- 이정수: 좌표 범위·stale·accuracy 검증과 거리 utility
- 김승균: 약속 시간창, 참여자, 양쪽 제출, 거리 임계값, 코드 fallback
- 정확 좌표 보존 기간과 로그 금지 정책은 공통 결정
- Front는 판정하지 않고 서버 상태만 표시

## 4. RiskSignal 계약

최소 event:

```text
eventId
sourceType
sourceId
actorUserId
targetUserId
occurredAt
signalType
metadata (원문 제외)
```

원천:

- 김승균: Greeting 무응답, Block, DIRECT leave/재접촉
- 노동훈: FriendRequest reject (`M3-BE3-106`)
- 이정수+AI: AI 맥락 위험 결과, Open Chat event
- 박선: 멱등 저장, 기간·점수 집계, Queue, 감사, Dashboard

## 5. Pet 삭제 연동

노동훈이 상태 전이를 소유하고 각 참조 도메인이 정책을 제공한다.

- 현재 대표 Pet은 다른 Pet을 먼저 대표로 활성화하기 전 삭제할 수 없음
- DIRECT/Open Chat 참여 기록과 과거 메시지는 보존 원칙 검토
- Friendship·Pending Request 정리는 회의 확정 범위가 아니며 별도 영향도 검토
- Setlog·게시글·후기의 과거 작성자 표기 정책
- Media 소유권·삭제 Job 처리
- MeetingCard·Footprint 기록 보존

## 6. Dashboard 집계 계약

- 박선이 API와 집계 쿼리를 소유한다.
- 각 도메인 담당자는 집계 가능한 상태값과 삭제·비공개 기준을 제공한다.
- 기본 7일, 최대 90일, `Asia/Seoul` 날짜 경계
- 최근 목록 10건 상한
- 원문·민감정보 제외
- Seed 포함 여부를 지표별로 문서화
