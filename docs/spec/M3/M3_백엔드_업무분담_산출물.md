## 2. 김승균

### M3 신규·확장 업무

#### A. 기존 BE-2 영역 유지 및 공개 계약 정리

- DIRECT 채팅 REST·WebSocket
- 인사, 약속 카드, 사용자 차단
- 사용자 신고와 관리자 신고 연계
- M3에서 다른 담당자가 재사용할 API, Event, 권한·오류 계약 정리

#### B. 만남 확인

- MeetingCard 이후 `만났어요` 제출 흐름 구현
- 이정수가 제공하는 좌표·accuracy·capturedAt 계약 사용
- 약속 시간창, 거리, 양쪽 제출 조건 판정
- 위치 정확도가 부족할 때 확인 코드 fallback 연계
- 중복·동시 제출 멱등 처리

#### C. 만남 후기·발자국

- 만남 확정 뒤 후기 작성 또는 건너뛰기
- 후기 제출 시 발자국 적립
- 동일 상대·동일 날짜 중복 적립 방지
- 후기·발자국의 권한과 상태 전이 검증

#### D. Chat 도메인 연계

- 박선의 Media 업로드 결과를 DIRECT 메시지로 전송
- IMAGE·VIDEO·SETLOG_SHARE 타입과 REST/WS DTO 적용
- 방 참여·차단·나가기 상태의 SEND 권한 처리
- 노동훈의 게시판 답변자 Pet을 기존 DIRECT 방과 연결

#### E. 위험 신호 연계

- DIRECT/인사/차단/채팅방 나가기에서 위험 신호 원천 event 제공
- 박선의 RiskSignal 수집·집계 계약과 연동
- 기존 신고 처리와 자동 탐지 검토 Queue의 관리자 동선을 협의

### M2 보완 업무

- DIRECT·인사·약속·차단·신고의 API·Event·권한 경계 문서화
- Media 첨부를 위한 ChatMessage 확장 구조 정리
- 예외 처리, 방 참여, 차단, 메시지 Evidence 권한 회귀 검증

### 완료 조건

- 약속→양쪽 확인→후기→발자국 흐름이 두 계정으로 동작
- DIRECT REST history와 WebSocket 실시간 메시지의 타입·payload 일치
- 이미지·영상·Setlog 공유에서 방 권한과 차단 정책 적용
- 원천 위험 event가 중복 없이 박선의 수집 계층으로 전달
- 게시판 답변자와 DIRECT 방 연결 성공

### 공유 필요사항

- 이정수와 Location/거리 판정 책임 확정
- 박선과 ChatMessage·Media·Evidence·관리자 계약 확정
- 노동훈과 답변 작성자 Pet 식별 계약 확정

## 3. 노동훈

### M3 신규·확장 업무

#### A. Pet 삭제

- Pet 삭제와 Active Pet 변경 정책 적용
- 삭제 시 Open Chat 참여·과거 기록 처리 정책 반영
- Friendship·Pending Request 정리는 확정 범위가 아니며 별도 영향도 검토
- 삭제 상태와 `deletedAt` 정합성 보장

#### B. 게시판 `한 수 배웠어요`

- 게시글 Reaction에 도움 표시 유형 추가
- 기존 LIKE의 `reactionCount`·`reactedByMe`를 유지하고 `helpfulCount`·`helpfulByMe` 추가
- 중복 반응 방지와 멱등 처리
- 포인트·발자국과 연결하지 않음

#### C. OAuth 로그인

- Google·Naver 로그인 구현
- 기존 User·JWT·Refresh Token과 연계
- OAuth 사용자는 별도 이메일 인증 없이 가입·로그인
- callback→loginCode→exchange 흐름과 신규 사용자 `/auth/oauth/signup` 구현
- 기존 동일 이메일은 별도 User 생성 없이 D-02 연결 정책 반영

#### D. Pet·Board 이미지 수정·삭제

- Pet 프로필 이미지 교체·삭제
- Board Post 첨부 이미지 수정·삭제
- 기존 Media 소유권과 Storage 정리 계약 재사용
- 원본 데이터와 Media link 정합성 유지

#### E. FriendRequest 위험 신호 event

- FriendRequest reject를 `RiskSignal` 원천 event로 발행
- 박선의 `M3-004` event schema와 eventId 멱등 계약 사용
- 거절 처리 트랜잭션과 event 발행 실패의 재처리 방식을 테스트

### M2 보완 업무

#### A. 대댓글

- Comment 부모·자식 관계와 조회 순서
- 최대 깊이, 부모 삭제, 권한 정책 적용

#### B. 게시판 장소 기능

- 게시글에 이정수의 Place 식별자 연결
- 게시글 조회에서 장소 요약 제공
- 지도 화면으로 이동할 계약 제공

#### C. Redis 적용 검토

- 실제 효과가 있는 조회 Cache 또는 동시성 Lock만 적용
- 측정 결과와 적용/미적용 근거를 남김
- 적용한 경우에만 Cache TTL·무효화 또는 Lock 실패 정책과 테스트 포함

#### D. 이미지 N+1 개선

- Pet 프로필·게시글 첨부 Media를 일괄 조회
- 박선의 공용 Media batch URL 계약 `M3-BE-MIA-102` 사용
- 페이지 크기 증가에도 SQL 수가 크게 증가하지 않는지 검증

### 완료 조건

- Active Pet을 포함한 Pet 삭제 상태 전이와 참조 정합성 검증
- Google·Naver 신규/기존 사용자 로그인 시나리오 통과
- 게시글 도움 표시의 멱등성과 누계 정합성 보장
- FriendRequest reject→RiskSignal event 계약 테스트 통과
- 대댓글·게시판 장소·이미지 수정·삭제 프론트 연동
- 이미지 조회 N+1 회귀 테스트 통과

### 공유 필요사항

- 김승균·이정수와 Pet 삭제 시 Open Chat 참여 기록 처리 협의
- 이정수와 게시판 Place DTO·지도 이동 계약 협의
- 박선과 Media batch·삭제 Job 계약 협의
- M3에서는 비로그인 공개를 도입하지 않고 로그인 기반 정책 유지

## 4. 박선

### M3 신규·확장 업무

#### A. 관리자 Dashboard

- User, Pet, Setlog, 게시글의 전체·기간 신규 통계
- 기간 신고와 열린 신고
- 위험 사용자, 열린 안전 검토, 유형별 감지 수
- 최근 신고·안전 검토 최대 10건
- 기본 7일·최대 90일, `Asia/Seoul` 날짜 경계
- `ADMIN`, `SUPER_ADMIN` 전용 권한과 집계 성능 검증

#### B. 채팅 이미지·영상 첨부

- 기존 Presigned Upload와 Media 완료 검증 재사용
- 이미지·영상의 소유권, MIME, 크기, 상태 검증
- ChatMessage와 Media 참조 관계 제공
- 조회 시 batch Media 서명, 만료 URL DB 저장 금지
- 김승균의 DIRECT, 이정수의 Open Chat 메시지 계약에 동일 payload 제공

#### C. Setlog 채팅 공유·상세 이동

- Setlog 상세에서 공유 대상 채팅방 선택
- `SETLOG_SHARE` 메시지에 `setlogId` 정본 저장
- 공유 카드용 Setlog·Media batch summary 제공
- 삭제·차단·비공개 시 접근 불가 상태 반환
- 카드 클릭 시 동일 Setlog 상세 route로 이동할 프론트 계약 제공

#### D. 거절 후 반복 접촉·관리자 검토

- 각 도메인의 RiskSignal을 멱등 저장·집계
- 동일 대상 반복 접근의 기간·횟수 규칙 적용
- 임계값 초과 시 관리자 검토 Queue 생성
- 자동 제재 없이 오탐·경고 기록
- 원문 별도 복제 금지, 필요 조회 시 감사 로그

#### E. 통합·배포

- Flyway 번호, 환경 설정, Unit·통합·WebSocket·Consumer 테스트 관리
- 발표용 Dashboard·Media·Setlog 공유·Risk seed
- 배포 E2E, 관측 지표, 장애 fallback, Runbook

#### F. 모니터링

- 정식 도입 범위는 결정 대기
- 최소 지표: HTTP p95/p99, Hikari pending, DB lock wait, 스토리지 backlog

### M2 보완 업무

- HlafBrain 관리자 코드를 기준으로 개인 Admin query·test를 선별 이식
- 관리자 권한 테스트 fixture와 기존 실패 정리
- Setlog/Pet/Board/Chat의 Media N+1 제거 지원
- Setlog 반응 Lock 경합 측정·보완
- StorageDeleteWorker의 실제 S3 삭제, retry, backlog, lease 검증
- Flyway, Kafka, WebSocket, S3/RustFS, Hikari 배포 설정 점검

### 완료 조건

- Dashboard 통계와 실제 DB가 일치하며 권한·날짜 경계 통과
- 이미지·영상 업로드→전송→실시간 수신→이력 재조회 동작
- Setlog 상세→공유→채팅 카드→동일 상세 이동 동작
- 위험 event→누적→Queue→관리자 검토·감사 흐름 동작
- batch 조회로 신규 Media·Setlog N+1 방지
- 8월 25일 배포 E2E, 8월 26일 코드 동결

### 공유 필요사항

- 김승균·이정수와 공통 ChatMessage/attachment 계약 확정
- 김승균과 기존 신고·관리자 코드 기준선 확정

- 김승균 만남 확인에 Location DTO·거리 판정 utility 제공

- 인기 경로 또는 가중치 정책은 AI 담당과 협의

- ELK 등 도입 여부와 기록 대상 결정

- 로그에 민감정보가 포함되지 않음

### 공유 필요사항

- AI 담당과 검열·산책 가중치 계약 확정
- 김승균과 Location·거리 판정·약속 카드 계약 확정
- 노동훈과 게시판 Place DTO 확정
- 박선과 Media payload·RiskSignal·관측 지표 확정

## 6. 공통 운영 원칙

- 공용 DTO·Event·Migration은 구현 전에 담당자와 리뷰어를 지정한다.
- REST, WebSocket, Kafka/Consumer에서 같은 메시지 의미를 유지한다.
- Media·Setlog·Place는 문자열 복제가 아니라 내부 ID 또는 provider ID로 연결한다.
- 위치·대화·관리자 조회는 최소 데이터와 감사 정책을 적용한다.
- Redis·Cache·Lock·ELK는 도입 자체가 목표가 아니라 문제와 완료 지표를 먼저 정의한다.
- 기능 범위가 밀릴 경우 필수 happy path를 유지하고 그래프·다중 첨부·고급 UI부터 줄인다.
