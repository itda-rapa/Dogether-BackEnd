# 같이놀개 최신 제품 정책

> 상태: 확정
> 우선순위: 기존 v13 문서와 충돌하면 이 문서가 우선한다.

## 1. 마일스톤

### M1

- 일반 이메일 회원가입
- 동네 직접 선택
- Pet 등록 및 등록정보 조회
- S3 시드 셋로그 영상 3개 조회
- 귀여워요·좋아요 반응
- 인사와 1:1 채팅
- 친구 요청과 친구 관계
- 약속 카드
- 신고와 차단
- 관리자 신고 처리
- 폴링 방식

### M2

- Google 로그인
- GPS 동네 확인
- 사용자 셋로그 업로드
- 지도·장소
- 만남 확인
- 후기·발자국
- 그룹 채팅
- 대화 맥락 검열

M1에서는 이메일 인증, 비밀번호 찾기·재설정, Push, 읽음 표시,
메시지 수정·삭제, 이미지·파일 첨부, 회원탈퇴를 제공하지 않는다.

## 2. 홈과 권한

- 우리 동네 이웃 목록은 폐기한다.
- M1 홈에는 S3에 미리 적재한 셋로그 영상 3개만 노출한다.
- L1은 시드 셋로그를 열람할 수 있다.
- L2는 활성 Pet을 선택한 사용자이며 인사·반응·채팅·카드를 사용할 수 있다.
- 사용자는 같은 `owner_user_id`를 가진 Pet 중 `deleted_at IS NULL`인 Pet을 최대 5마리까지 등록할 수 있다.
- `SUSPENDED` Pet도 삭제되지 않았다면 한도에 포함하고, `DELETED`이면서 `deleted_at IS NOT NULL`인 Pet은 제외한다.
- Active Pet은 삭제할 수 없다. 다른 Pet을 Active로 바꾼 뒤 삭제한다.
- 관리자가 Active Pet을 정지하면 `users.active_pet_id`를 `NULL`로 바꾸고
  사용자는 다른 Pet을 선택할 때까지 L1이다.

## 3. Pet 삭제와 인증

- 일반 Pet 삭제 시 해당 Pet의 Friendship을 삭제한다.
- 양방향 PENDING 친구요청을 취소한다.
- 과거 친구요청·채팅·메시지는 보존한다.
- Pet은 `status = DELETED ↔ deleted_at IS NOT NULL`의 양방향 불변조건을 따른다.
- 일반 삭제는 `status=DELETED`와 `deleted_at`을 같은 트랜잭션에서 변경한다.
- 관리자 정지는 `status=SUSPENDED`, `deleted_at=NULL`로 유지하므로 Pet 한도 슬롯을 늘리지 않는다.
- 인증 근거 필드를 수정하면 인증 배지를 해제한다.
- 보호자 이름·생년월일은 등록정보 조회 요청에만 사용하고 저장하지 않는다.

## 4. 인사와 채팅

1. 셋로그에서 인사한다.
2. DIRECT 방을 즉시 만든다.
3. 최초 인사 메시지를 저장한다.
4. 상대 답변 전에는 추가 메시지를 보낼 수 없다.
5. 상대가 답변하면 자유롭게 대화한다.
6. 필요한 경우 이후에 친구를 요청한다.

세부 규칙:

- 친구가 아니어도 인사·채팅·약속 카드 생성이 가능하다.
- 친구는 채팅 게이트가 아니라 연결 영속성이다.
- 인사는 Pet당 하루 10명까지 가능하다.
- 재인사 기능은 없다.
- 최초 인사 후 24시간 무답변이면 Greeting은 `EXPIRED`로 보존한다.
- 신고되지 않은 무답 ChatRoom·최초 메시지·Participant는 물리 삭제한다.
- 신고된 방은 증거 보존을 위해 삭제하지 않는다.
- 답변한 비친구 방은 30일 무활동 시 `ARCHIVED`로 전환한다.
- 보관된 방에서 메시지를 보내면 `ACTIVE`로 복구한다.
- 친구 삭제 후에도 기존 방과 메시지는 유지되고 대화할 수 있다.
- M1 메시지 유형은 `TEXT`, `CARD`, `SYSTEM`이다.
- 사용자가 직접 보낼 수 있는 유형은 `TEXT`뿐이다.
- 카드·시스템 메시지와 폴링으로 상태 변화를 전달한다.

## 5. 친구

- 친구 관계와 친구요청은 Pet pair 기준이다.
- Pet당 친구는 최대 50명이다.
- `friend_requests`는 요청 이력, `friendships`는 현재 관계를 나타낸다.
- A→B PENDING 중 B→A가 요청하면 자동수락하고 Friendship 한 행을 만든다.
- PENDING 요청은 7일 후 만료한다.
- 거절 후 즉시 재요청할 수 있다.
- 같은 User가 소유한 Pet끼리는 인사·친구요청·셋로그 반응을 금지한다.

## 6. 차단과 신고

- 차단과 신고는 M1이며 서로 독립적이다.
- 신고해도 자동 차단하지 않는다.
- 차단 시 Friendship을 삭제하고 양방향 PENDING 요청을 취소한다.
- 차단된 사용자는 서로 인사·메시지를 보낼 수 없고 콘텐츠도 노출되지 않는다.
- M1에서는 차단 해제를 제공하지 않는다.
- 신고 접수 시 관리자는 해당 DIRECT 방 전체 대화와 신고 사유를 확인한다.
- 욕설·비속어 자동 차단과 M1 AI 검열은 제공하지 않는다.

## 7. 셋로그와 반응

- M1 셋로그는 시드 영상 3개 조회만 제공한다.
- 사용자 촬영·편집·업로드는 M2다.
- 귀여워요와 좋아요는 동시에 누를 수 있다.
- 인사해요는 Reaction이 아니라 Greeting이다.
- M1 반응 알림은 없고 카운트만 표시한다.
- 자기 Pet의 셋로그에는 반응할 수 없다.

## 8. 약속 카드

- 친구가 아니어도 생성할 수 있다.
- 최근 30개이면서 24시간 이내 메시지만 AI에 전달한다.
- AI 실패·지연 시 빈 폼을 제공한다.
- 확정 시 종류·날짜·시각·장소가 필수다.
- M1 참여 Pet은 2마리로 고정한다.
- 양쪽 참여 Pet 모두 취소할 수 있다.
- M1에서는 카드를 수정하지 않는다. 변경하려면 취소 후 다시 생성한다.

## 9. 회원탈퇴 — POST-M1

- 회원탈퇴 API와 정리 Service는 M1 완료 범위에서 제외한다.
- `DELETE /me`, Refresh Token 폐기, Pet 최종 상태, Friendship·친구요청 정리,
  개인정보 익명화·파기, 비동기 재시도는 POST-M1에서 함께 설계한다.
- DB의 `WITHDRAWN`, `withdrawn_at` 같은 미래 확장 구조는 유지할 수 있지만
  이를 M1 회원탈퇴 구현 완료 증거로 사용하지 않는다.
- 기존 채팅·신고 증거의 보존기간과 접근 통제도 POST-M1 정책에서 확정한다.

## 10. 외부·운영 확인

- 보호자 이름·생년월일 처리 약관
- 개인정보·채팅·신고 증거 보유 및 파기기간
- 실제 PostgreSQL Flyway 제약·인덱스 구현

## 11. M1 API 기본값

- Pet 생성 트랜잭션에서 생성 전 미삭제 Pet 수가 0인지 판정해 내부 `firstPetCandidate`를 확정한다.
- Pet 생성 Commit 후 후보인 경우에만 별도 트랜잭션으로 Active Pet 지정을 시도한다.
- Pet 생성 단계의 owner User 잠금·동시 수정 충돌은 Pet을 Commit하지 않고
  `409 CONCURRENT_UPDATE_CONFLICT`로 처리한다.
- 생성 Commit 이후 자동 Active 지정 단계에서 비관적 잠금 실패로 분류된 동시성
  오류가 발생하면 생성된 Pet을 유지하고 `201 Created + RETRY_REQUIRED`를 반환한다.
- 자동 Active 지정의 DB 연결 장애·무결성 오류·불변조건 위반·코딩 오류는
  `RETRY_REQUIRED`로 숨기지 않고 기존 오류 흐름으로 처리한다. 이때 선행 Pet 생성은
  이미 Commit된 상태일 수 있다.
- `firstPetCandidate=false`이거나 이미 Active Pet이 있으면 `NOT_APPLICABLE`을 반환한다.
- Active Pet이 없는 L1 사용자는 `PUT /me/active-pet`으로 본인 소유의 `ACTIVE`·미삭제 Pet을 선택할 수 있다.
- 등록정보 Provider는 M1에서 동기 처리한다.
- 등록정보 Attempt는 Provider 처리 완료 후 `SUCCEEDED`, `REJECTED`, `FAILED` 중
  최종 상태로 저장하며 DB에 `PENDING`을 저장하지 않는다.
- canonical 등록번호가 없으면 `REJECTED`로 처리해 인증 배지를 발급하지 않되 직접 Pet 등록은 허용한다.
- Pet PublicTag는 User PublicTag와 별도 Namespace다. trim한 nickname의 앞 25개
  Unicode code point와 `#XXXX` suffix로 만들고 Unique 충돌 시 새 트랜잭션에서
  최대 5회 재시도한다.
- `GET /pets/me`는 Active Pet을 먼저, 나머지는 `createdAt ASC, petId ASC`로 반환한다.
- Pet nickname은 trim 후 1자 이상이며 M1 `profileUrl`은 null이다. 기본 이미지는
  클라이언트가 표시한다.
- M1 Pet 생성은 Idempotency-Key를 제공하지 않는다. 클라이언트는 요청 중 버튼을
  잠그고 timeout·5xx 후 POST를 재시도하기 전에 `GET /pets/me`로 생성 여부를 확인한다.
- 동일 신고자·DIRECT 방의 `OPEN` 신고는 하나만 유지한다.
- 중복 신고 요청은 최초 신고의 사유·상세를 변경하지 않는다.
- 약속 카드 종류는 `WALK`, `PLAY`, `OTHER`다.
- 신고 사유는 `HARASSMENT`, `SPAM`, `OTHER`이며 `OTHER`는 상세 사유가 필수다.
- 관리자 신고 처리는 `DISMISSED`, `WARNING`만 제공한다.
- `WARNING`은 사용자에게 노출하지 않고 관리자 처리 이력만 남긴다.
- 종결된 신고에는 추가 조치를 허용하지 않는다.
- Pet 프로필 이미지 업로드와 범용 미디어 업로드 API는 M1에서 제공하지 않는다.
- 일반 USER가 범용 `/media/**` 업로드 흐름을 사용할 수 없으며 위반 시 `MEDIA_PURPOSE_FORBIDDEN`을 반환한다.
- 차단된 DIRECT 방은 사용자 목록에서 숨기되 신고 증거 데이터는 보존한다.
- 정적 `04_M1_OpenAPI.yaml`만 REST 계약 정본으로 사용하며 런타임 `/v3/api-docs` 대조를 M1 Gate로 요구하지 않는다.
- 별도 HTTP Status는 정적 OpenAPI, `ErrorCode`, 구현, 테스트와 endpoint 오류
  매트릭스를 같은 PR에서 계약 우선으로 변경한다.
